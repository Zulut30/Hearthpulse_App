# Adding a counter

Counters are small chips on the overlay (`counters` panel for Constructed, `bg-counters` for Battlegrounds) that
show a running value the game does not show directly. Each one is a single definition in Core; the settings list and
the overlay pick it up automatically through `.All` / `Build`. Background: [hearthpulse-tracking](../hearthpulse-tracking/SKILL.md)
(finding tags, no hidden information), tests: [hearthpulse-testing](../hearthpulse-testing/SKILL.md).

Specs to update with every counter: `docs/counters-constructed.md` ("Added counters" table + "Skipped") and
`docs/counters-battlegrounds.md` ("Confirmed by the logs" / "From the tag enumeration ... waiting" / "Skipped").
Ideas come from HDT/HSReplay counter lists (names only - see the licence rules in
[hearthpulse-data-sources](../hearthpulse-data-sources/SKILL.md)); values come from our own log reading.

## Step 0: where does the value come from?

Decide the source and write it in the spec row before coding:

| Source | Example | How |
|---|---|---|
| Player tag the game keeps | `HERALD_COLOSSAL_AMOUNT`, `CORPSES`, `NUM_SPELLS_PLAYED_THIS_GAME`, `CTHUN_ABILITY1..4_USED` | `c.Tag("NAME")` - confirm the tag in a real log |
| Tracker events | spells cast by school, friendly deaths, cards drawn this turn | `CounterTracker.PlayerLog` (`Played`, `Summoned`, `Died`, `Destroyed`, `Discarded`, `Attacks`, `Drawn`, `Choices`...) |
| Card table | Libram/Leyline cost, Excavate tier, Blood Runes, Protoss | `CounterCards.Sources[key]` etc., generated |

A tag seen only as a bare number with no card to check it against stays **unconfirmed** - do not guess its meaning.

## Constructed counter

File: `src/Hearthpulse.Core/Tracking/Counters/Counters.cs`, array `Defs` of
`CounterDef(string Id, string Title, string Description, Func<CounterContext, CounterValue?> Compute)`.

1. Add the definition in display order (ids are kebab-case, unique, stable - they are keys in `AppSettings.CounterModes`):
   ```csharp
   new("herald", "Herald", "Heralds this game. Every two Heralds upgrade your class Colossal.", c =>
   {
       var n = c.Tag("HERALD_COLOSSAL_AMOUNT");
       var next = 2 - n % 2;
       return new(n.ToString(CultureInfo.InvariantCulture), n % 2 / 2.0, [$"Next Colossal upgrade after {next} more Herald{...}."], n > 0, Goal: 2);
   }),
   ```
   `CounterValue(Value, Progress, Details, Active, Counted, Parts, Goal)`:
   - `Value` - the chip text (invariant culture for numbers);
   - `Details` - tooltip lines under the `Description`;
   - `Active` - the value itself makes the counter relevant (shown in Auto even without a related card);
   - `Counted` - card ids that were counted (shown grouped in the tooltip);
   - `Parts` - `(CardId, Done)` checklist (e.g. C'Thun abilities); `Goal` - segments when <= 10, bar otherwise.
   - Return `null` to hide the counter for that player (e.g. hidden info for the opponent).
   Helpers in the same file: `Num`, `Ids`, `PlayedNum`, `Goal`, `Next`, `Countdown`; context: `c.Tag`, `c.Played()`,
   `c.PlayedIds()`, `c.Plays()`, `c.Deaths()`, `c.Source(key)`, `c.SourceCards(key)`, `c.OwnTurn`, `c.Log`, `c.Cards`.
2. If you need a new kind of event, record it in `CounterTracker.cs` (`PlayerLog`) - per player, visible events only.
3. **Related cards** (what makes the chip appear in Auto): add a regex for the card text to `PATTERNS` (or the card
   name to `NAME_PATTERNS`) in `tools/counters/gen_counter_cards.py` under the **same id**; per-card amounts go to
   `SOURCE_PATTERNS` (`(?P<n>\d+)` = amount, `(?P<twice>...)` doubles). Then regenerate (step below). `Counters.cs`
   reads `CounterCards.Sources[key]` directly - a missing key throws.
4. Relevance is automatic: Auto shows the chip when the player's deck or seen cards contain a related card
   (`CounterCards.Related[id]`) or `Active` is true. Opponent chips are gated by `ShowOpponentCounters`.

### Regenerate `CounterCards.g.cs`

The script does not download anything; give it HearthstoneJSON **enUS** data (patterns match English text):

```
curl -sSL -o <new empty dir>/cards.enUS.json https://api.hearthstonejson.com/v1/latest/enUS/cards.json
python -I tools/counters/gen_counter_cards.py <dir>/cards.enUS.json src/Hearthpulse.Core/Tracking/Counters/CounterCards.g.cs
```

It prints a count per id - a new id with 0 cards means the regex is wrong; a huge count means it is too broad.
Check the diff of `CounterCards.g.cs` for unrelated churn (a fresh patch changes other ids too - fine, but say so
in the commit). Never edit the `.g.cs` by hand. (Dry run on 2026-10-23: regenerating from the live data reproduced
the committed file byte for byte.)

## Battlegrounds counter

File: `src/Hearthpulse.Core/Battlegrounds/BattlegroundsCounters.cs`, array `Defs` of
`CounterDef(string Id, string Title, string Description, bool Confirmed, string[] Related, Func<CounterContext, CounterValue> Compute)`;
tracker `Battlegrounds/BattlegroundsCounterTracker.cs` (local `Died`, `Summoned`; combat copies with
`COPIED_FROM_ENTITY_ID` excluded).

- Id starts with `bg-`; local player only.
- `Related` is written inline (normal card ids; trinkets `BG.._MagicItem_...` too) - no generator.
- `Confirmed = true` only after the value was matched with what the game shows in a real log; otherwise return
  `Missing()` (the chip shows the dash `NoData`) and list it under "waiting" in the spec.
- Relevance: `value.Active || (Confirmed && a related card is visible)` (tavern, hand, board, trinkets, hero power).
- Helpers: `TagStats`, `EnchantStats` (player enchantments via `TAG_SCRIPT_DATA_NUM_1/2`), `Normal()` (golden -> normal).
- The file has its own private `CounterValue` record, which adds `Title` and `IconCardId` overrides
  (`Missing() with { Title = ..., IconCardId = ... }`).

## UI: nothing to add for a plain counter

- Settings: "Counters and mulligan" card lists `Counters.All` (`MainViewModel.Counters.cs`, `CounterRows`,
  `SetCounterMode("id|Mode")`) and `BattlegroundsCounters.All` (`MainViewModel.BgCounters.cs`) in **both** UIs.
  Modes: `CounterMode { Auto, Always, Off }`, stored in `AppSettings.CounterModes` (missing = Auto).
- Overlay: chips are built by `CounterChip.From(view, expanded)` in `Overlay/OverlayModels.cs` (both UIs; tooltip =
  Description + Details; `Counted`/`Related` cut to 8 with "+N more"). Constructed chips: `RebuildCounters` in
  `OverlayViewModel.Live.cs`; BG chips: `OverlayViewModel.BgCounters.cs`.
- Change these only if the counter needs a new kind of visual (then follow [hearthpulse-overlay-panel](../hearthpulse-overlay-panel/SKILL.md)
  in both UIs).

## Tests

- Constructed: `tests/Hearthpulse.Tests/CountersTests.cs` - build a game with `Play(...)`, `Cast`, `PlayFromHand`,
  `Die`, read with `Value(View(state), "id")`:
  ```csharp
  [Fact]
  public void Improving_cards_count_earlier_copies()
  {
      var view = View(Play([.. Cast(50, "YOG_514", 1, "MINION"), .. Cast(51, "YOG_514", 1, "MINION")]));
      Assert.Equal("3-Cost Spell", Value(view, "chaotic-tendril"));
  }
  ```
  Cover: the value, relevance (related card in deck), opponent behaviour (null when hidden), golden/copied cards.
- Battlegrounds: `tests/Hearthpulse.Tests/BattlegroundsCountersTests.cs` (`Play`, `Start`, `Entity`,
  `PlayerEnchant`, `PlayerTag`, `Counter`). It pins totals - update the expected count of all BG counters and of
  unconfirmed ones when you add one.
- Real logs: replay your kept logs and keep the output as evidence (the last round saved
  `constructed-counters-real-log-run.txt` in the shared notes). `CounterScene.FromLatestLog` / `CounterScene.Synthetic`
  feed the render scene.

## Verify

1. Tests: baseline + new, none failing.
2. Render both UIs and look at `overlay-counters*.png` / `overlay-bg-counters.png` and `main-settings-counters.png`
   ([hearthpulse-visual-check](../hearthpulse-visual-check/SKILL.md)): title fits, tooltip lines wrap, no clipping.
3. Spec row added (id, title, what it counts, cards, source, goal), skipped ideas listed with the reason.
